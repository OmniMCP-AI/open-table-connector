# Portable Temporal Plan v1 Semantics

This document is normative for `otc.portable-temporal-plan/v1`. An implementation
MUST apply the rules below; a producer or consumer MUST reject a document that
violates a structural rule in the published schema or a semantic MUST here.

## Time ranges and ordering

All timestamps MUST be RFC 3339 UTC values with a `Z` suffix and at most nine
fractional digits. A range `[start, end)` includes `start` and excludes `end`;
`start` MUST be strictly earlier than `end`. `at_or_before` and `at` are
inclusive instants. Projection order is the order of the `projection` array.
Group keys and output columns MUST preserve their declared order. `output_order`
is applied after the operation and MUST refer only to columns in the operation's
output shape. Ascending and descending ordering MUST use stable null ordering:
nulls sort after non-null values in ascending order and before non-null values in
descending order. Ties MUST retain source order unless a declared key resolves
them.

## Duplicate policy and latest/as-of

Rows with the same series key and timestamp are duplicates. `replace-latest`
selects the row with the greatest ingestion timestamp; an ingestion timestamp
MUST be present for that policy. An exact tie MUST be resolved by the source
sequence in encounter order. `latest` returns one row per series key at or before
the requested instant. `as_of` returns all rows in the half-open range that are
visible at the requested instant, with duplicate policy applied first.

## Buckets

Fixed buckets are anchored at `origin + offset_ns`. A timestamp belongs to the
bucket whose lower boundary is the greatest boundary less than or equal to the
timestamp. Calendar buckets are generated by repeatedly applying the declared
calendar interval in the declared IANA timezone; labels MUST round-trip through
UTC and MUST be strictly increasing. A bucket interval is left-closed and
right-open. Bucket labels MUST be generated as a domain independent of observed
rows, and a generated label MUST never be silently skipped because a timezone
transition changes its wall-clock duration.

## Aggregates and nulls

`count` is SQL `COUNT(*)`: it counts rows in the bucket and MUST have
`value_field: null`. Every other aggregate (`min`, `max`, `sum`, `avg`, `first`,
and `last`) MUST name a value field. Null input values are ignored by `min`,
`max`, `sum`, and `avg`; an all-null or empty input produces null. `first` and
`last` select the first or last non-null value in operation order and produce
null when no non-null value exists. `count` counts rows regardless of value
nullability. Group keys remain present even when all aggregate values are null.

## Gap fill

Gap fill MUST construct the complete bucket domain first, then left-join observed
aggregates onto that domain for every observed group. It MUST preserve generated
domain rows and MUST NOT claim that generated rows were examined at the source.
`null` fill sets a value to null, `constant` uses its declared scalar,
`locf` carries the last observed non-null value forward, and `linear` uses
Polars positional interpolation between observed non-null values; it is not
time-weighted. Values outside interpolation endpoints remain null. Fill rules
apply only to declared aggregate columns.

## Limits and receipts

`ResourceBounds.max_rows` and temporal `ResourceBounds.max_rows` are hard
completeness bounds. A complete result MUST fit within the bound; a partial read
MUST fail with a resource-limit error and MUST NOT claim completeness. A
presentation limit such as CLI `--limit` is not a completeness receipt and MUST
be applied after a complete read. Receipt counts MUST report actual examined and
returned rows; generated gap-fill rows MAY make returned rows exceed examined
rows.

## Wire identity

The v1 wire fields and hash identities remain those defined by the existing
implementation. Their exact byte inputs are documented separately in
`hash-identities-v1.md` when available; implementations MUST NOT silently change
v1 digest inputs.
